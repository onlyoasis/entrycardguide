## 实施设计要求

### A. 可索引的完整第三语言

- 保留英文根路径和简体 `/zh/`；繁体稳定使用 `/zh-hant/`。
- 新增完整 Hugo 语言配置、i18n 和内容覆盖。优先沿用文件后缀方式 `.zh-hant.md`，确保Hugo翻译集合识别正确。
- 标题、description、正文、FAQ、图片替代文字、共享UI、费用描述、页面卡片、国家名称、页脚和404都要完整繁体。保留官方英文表单原字段名、专有名词和例值，必要时附繁体解释，不能把英文官方字段名误当漏翻而删除。
- 可使用 **构建时或一次性可重复的OpenCC转换＋人工/模型校对＋术语覆写** 降低成本；新增依赖限构建端，浏览器端仍为零npm依赖、无翻译网络请求。工具应来自官方/可信包源，锁定依赖。
- 不能把HTML全文或源码所有字符串盲目转换；保护URL、slug、ID、shortcode参数、正则、格式约束、日期、数值、金额、枚举、表单示例与官方原文。中文锚点随标题变化时，修正对应的站内引用并验证真实锚点存在。
- 采用清楚的繁体用词，如護照、航班、電子郵件、欄位、填寫、官方網站。以通用繁体服务台湾／香港读者，不凭语言推断国籍或添加针对台湾护照的适用规则。

### B. 数据和交互

- 盘点并消除繁体路径落入英文或简体分支的问题：`eq .Lang "zh"`、`$isZh`、`_en/_zh`选择、固定 `/zh/`、JSON payload、客户端硬编码、搜索索引与动态字符串均须覆盖。
- `data/fields/*.toml`、`data/official_urls/*.toml`、changelog和roster的展示文案需提供繁体来源。使用明确locale字段或翻译覆写，保持机器规则和官方网址单一真源，不复制整套法规数值形成第二真源。
- 校验器只本地校验，**验证规则逻辑不变，不修改 `validator.ts` 的约束行为**。通过data里的展示label/help/errors及构建期选择给繁体页面提供完整提示。缺少error消息时补齐所有真实可触发的提示，不依赖英文兜底。如发现必须改框架才能本地化，先给出文件/调用链证据，保持算法不变并交Codex审查。
- 决策树的状态ID、选项value/next、start、国家覆盖与分支规则不变；本地化问题、选项、结果、说明、按钮及站内guide/fallback链接。官方外链原样保留。全部结果须指向对应繁体指南。
- 搜索支持繁体国家名／常用简繁查询，搜索结果落在当前语言；官方目录筛选、计数、清除／无结果提示完整本地化；无JS目录和决定工具fallback可用。

### C. SEO和维护

- HTML lang与hreflang使用清楚统一的映射：en、zh-Hans、zh-Hant；简体路径保持 `/zh/`。HTML与sitemap的同页对应关系一致，互相返回并包含自身。
- 每个翻译页self-canonical，x-default保留英文对应页。不存在的页面不输出alternate；不把繁体页canonical指回简体。不要把语言标记视作访问限制。
- 根sitemap包含第三语言子sitemap，robots列出相应sitemap。JSON-LD inLanguage／WebSite语言列表、FAQ、Breadcrumb等本地化；OG locale按平台实际支持的地区映射处理，不能机械照搬不合法值。
- 保留站内链接、外链、联盟参数、CSP、robots与现有SEO检查；增加第三语言、完整互译集、锚点和覆盖门禁。CI的真实 `npm run build:prod` / `npm run check:seo` 必须包含必要准备步骤，不能只有你临时手工运行才能构建。
- 翻译不是法规重新核验。保留原 `last_verified`、规则lastVerified、来源和内容核验日期；新增文件的Git时间不能伪装成今天重新核验规则。区分内容核验与翻译更新。若需要调整展示日期来源，仅作本次必要更改并回归原语言，不全站冒然刷日期。
- 提供后续维护命令／流程：新增国家或更新简体时如何同步繁体、如何发现缺失和陈旧译文、怎样保护人工术语覆写。不要靠每次重新全量覆写人工修订。
