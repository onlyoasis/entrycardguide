## 0. 这份文档怎么读

**文档里给出的"候选官方域名""候选表单名""费用姿态"全部是待核查项，不是结论。**
动手前必须逐条对官方网站核实。查到的实际情况与本文档不符时，**以实际为准**，
并在该批次的回复里单列一节说明差异（哪一国、本文档写了什么、实际是什么、依据哪个官方页面）。

不允许出现的行为：
- 照抄本文档的域名/费用而不打开官方页面；
- 实测与本文档预期不符时，改本文档的预期去迁就实现；
- 查不到就编一个看起来合理的值。

### 内容（6 份，中英成对）

5. `content/{key}/_index.md`

### 接线（2 处）

### 不做的两件事

13. **不创建 `is-ivisa-official` 页面。** 该页型已于 2026-08-10 全站下线。

    仓库里老国家还留着这些字段，那是历史包袱，不要复制到新国家。

## 3. 硬性规则（红线，违反即打回）

### 3.1 事实

- **官方 URL 必须打开正文读过**，HTTP 200 不算核验。要能说出这个页面是哪个机构办的、写了什么。
- **只认政府域名**（`.gov.xx` / `.go.xx` / `.gob.xx` / `.govt.xx` 等国别政府后缀，或官方页面自身指向的入口）。
  某国如果把官方入口外包给商业承包商（域名不是政府后缀），**不许把它当"官方域名"轻描淡写带过**：
  必须在正文里写清楚"这是政府指定的承包商，域名不是政府后缀，核对方式是从政府页面点进去"。
- **费用不许编。** 查不到确切金额，或金额按国籍/时长变化，就照 `turkey` 的写法：
  `fee_en = "Varies by passport"` / `fee_zh = "按护照而定"`，正文举当前可查到的例子并注明会变。
  免费国家 `fee_en` 必须**恰好**是 `"Free"`（`layouts/_default/list.html` 用 `ne (lower .fee_en) "free"` 判断收费与否）。
- **三个日期同日**：`data/official_urls/{key}.toml` 各条目的 `last_verified`、`data/rules/{key}.json` 的
  `lastVerified`、以及 6 份内容文件的 `date`/`lastmod`，全部写**实际核验当天**的日期。
- 某国如果经核查**根本没有官方线上入境表/旅行授权/电子签**，
  **不要硬造一个国家页**。停下来报告，并从第 6 节的备用池里换一个。

### 3.2 字段规则的诚实性（本轮最容易翻车的地方）

`data/rules/{key}.json` 会被 `{{< validator >}}` 直接渲染成"官方校验规则"，
`layouts/_default/how-to-fill.html` 的默认导语原文是
*"With the exact regex the official site enforces, the error message it returns"*。
所以：

- `pattern` 字段**只有在真正看到官方表单的 HTML 属性/公开的官方格式说明时才能写**。
  没看到就**整个 `pattern` 键省略**，只保留 `label` / `required` / `maxLength` / `help` / `errors`，
  且这些值必须来自官方公开说明。
- `data/rules/{key}.json` 顶层的 `source` 字段必须如实记录来源，例如
  `"https://xxx.gov.yy 表单页 HTML 属性，2026-08-30 抓取"` 或
  `"https://xxx.gov.yy/faq 官方填写说明，2026-08-30；表单本身需登录，未能读取 HTML 属性"`。
- **只要没能读到实时表单的校验属性**，就必须在 `[meta]` 里设置
  `fields_intro_en` / `fields_intro_zh`，改写 how-to-fill 页的导语，
  不得让页面声称"官方正则 + 官方原话错误提示"。（先例：`australia`。）
- `data/fields/{key}.toml` 的 `[[errors]]` 数组里，`code` 必须是**官方页面真实出现过的错误文案**。
  一条都拿不到就**整个 `[[errors]]` 数组省略**（layout 用 `{{- with $errors }}` 包着，缺失不会报错）。

### 3.3 结构约束（构建期会炸的地方）

- `data/fields/{key}.toml` 里每个 `[[fields]]` 的 `key`，**必须**能在 `data/rules/{key}.json` 的
  `fields` 对象里找到同名键。找不到 → `index $rules $f.key` 取到 nil → 模板炸。
- `data/rules/{key}.json` 每个字段的 `type` 只能取
  `passport | date | flight | name | email | phone | text | nationality`。
  前 6 个有真实校验逻辑，后 2 个走 `default: return {ok:true}`（仅作展示，沿用现有国家的写法）。
- `[meta]` 必填键（缺一个就有页面渲染出空白或报错）：
  `flag`、`name_en`、`name_zh`、`form_code`、`guide_slug`、`form_key`、
  `form_name_en`、`form_name_zh`、`since_en`、`since_zh`、`fee_en`、`fee_zh`、`suffix`、`form_type`、
  `field_count`、`sections`、`time_needed_en`、`time_needed_zh`、`output_en`、`output_zh`。
- `form_key` 必须等于同一个 TOML 里主表条目的节名，也必须等于 roster 那一行的 `formKey`。
- `guide_slug` 必须等于 `content/{key}/` 下主表 markdown 的文件名（不含扩展名），也等于 roster 的 `guideSlug`。
- `form_type` 三选一：`arrival_card` | `travel_authorization` | `evisa`。
  ESTA / ETA / eTA 这类**不是签证**，选 `travel_authorization`，不要选 `evisa`。
- 决策树节点 schema（见 `assets/js/decide.ts`）：
  - question：`{"type":"question","label":...,"options":[{"value","label","next"}]}`
  - result：`{"type":"result","country","summary","forms":[{"name","fee","url","guide","agency","deadline?"}],"note?"}`
  - `guide` 必须是站内真实路径 `/{key}/{guide_slug}/`；`country` 必须等于 `{key}`。
  - 新增节点后 `states` 里不能有任何 `next` 指向不存在的 state。
  - `lastVerified` 更新为本轮核验日期。
- roster 那一行的字段：`key en zh flag formKey formCode guideSlug fee subEn subZh`，
  `fee` 只能是 `"free"` 或 `"paid"`。

### 3.4 "很多人根本不需要这份表"的国家

免签比例高的国家（本轮里 Georgia、Morocco、Uzbekistan、Azerbaijan 等都属于这一类），
**必须资格先行**，照 `turkey` 的做法：
- 决策树第一问是护照资格，免签路径给一个 `forms: []` 的 result，note 写明"不需要任何表，谁收钱谁是中介"；
- 主表页第一节就是"你可能根本不需要它"，然后才讲怎么申请；
- 页面标题走"check whether you need one before paying"方向。

把免签旅客推去付费申请，是本站最不可接受的错误。

### 3.5 写作风格（`docs/README.md`）

英文禁用：`delve`、`crucial`、`comprehensive`、`nuanced`、`furthermore`、`moreover`；禁止长破折号单独成句。
中文禁用：「关键在于」「让我来分解一下」「重要的是」「值得注意的是」这类开场套话。
要用：短句、具体数字、具体域名、真实的表单约束（字符上限、日期格式、官方错误文案）、真实用户视角。
中英两版是**同一份事实的两种表达**，不是机器互译；中文版标题要瞄准中文搜索词。

### 3.6 Git

**执行方不执行任何 git 命令**（不 add / 不 commit / 不 push / 不切分支 / 不 stash）。
提交由 Claude 在逐批验证后串行完成。

- **申根/欧盟国家（法国、西班牙、意大利、德国、希腊等）不在本轮范围。**
  ETIAS 尚未成为所有旅客都能填的现行表单，没有可写的"填写指南"。
  如果执行过程中发现 ETIAS 已全面生效，**报告，不要自行加入**。
- 不新增任何 i18n key。若某处文案确实缺 key，报告，不要自己加（加 key 必须 `en.yaml` 和 `zh.yaml` 同时改，属于跨批次改动）。
- 不修改 `tailwind.config.js`、不引入新配色/阴影/圆角、不引入浏览器端 npm 依赖。
