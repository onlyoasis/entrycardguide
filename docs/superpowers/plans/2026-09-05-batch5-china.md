## 目标与交付物

中国页面回答：官方网址、费用、适用人群与豁免、什么时候填、护照上传、日期、境内地址、邀请方联系方式、回执及更正流程的已知边界。

六个内容文件：`content/china/` 下的 `_index`、`arrival-card`、`how-to-fill`，中英成对。四份数据：`data/official_urls/china.toml`、`data/rules/china.json`、`data/fields/china.toml`、`data/changelog/china.toml`。

中国子任务只修改以上文件及本任务书、事实表、指定执行报告。共享 roster、decision、JS、i18n、config、CSS 由主控负责，本子任务不得修改。主控追加授权唯一模板例外：how-to-fill 的 H1 支持 `meta.fields_title_en/zh` 覆写，未设置时保留原有输出。不得执行任何 Git 命令或提交、推送、发布。

## 修复要求

1. 撤下中国四个主表/填写页面的 validator shortcode。使用现有 `fields_intro_en/zh`、`fields_walkthrough_en/zh` 覆写默认预检和全表顺序承诺。公共 validator 不动。H1 使用新增的可选 `fields_title_en/zh`，避免把所选资料项标题写成全表严格顺序。
2. 护照上传只写 JPEG/PNG；说明材料 PDF 单列。102400 bytes 在护照路径是压缩后大小，在说明材料 PDF 路径是原始大小。不得承诺小文件一定通过。
3. 邀请组仅在回答有邀请方后展开；单位或个人姓名按邀请类型条件必填，电话在该组内必填。不要自动将游客的酒店当邀请单位。住宿地址另填。
4. 按当前普通 `stepData` 五项说明流程，不把入境类别、回执翻译词条拼为六步。八张卡是本站选列，分四个指南组，`field_count=8`、`sections=4`；不是官方全量计数。卡片顺序跟普通组件实际流程。
5. 详细地址 100 字节、单位名称 200 字节、个人邀请人姓名 32 字节。个人电话 30 字符且保留 `+`/数字；邀请电话 12 字符且只保留数字，勿混用。
6. 详细地址和单位名称的占位提示不列为已证实错误。删除无普通控件证据的境内联系电话卡，用护照上传卡补齐选列。
7. 免费归因国家移民管理局提示。删除未经验证的存档及被误当入口的办事指引子页。撤销“中文错误未公开”的结论。
8. 缺少提交后更正、回执邮件送达、全部渠道一致性等证据时说明范围；不承诺柜台一定能修正错误。
