# 页面宽度与描述文字复查

基线：`b6015a0`。日期：2026-09-05。

## 上轮遗漏

上轮“无整页溢出”不代表内部宽度分配正确。用户复查指出目录独宽、描述文字仍提前换行。
实测 1920px 视口：目录 main 为 1440px，但其页头、页脚及其他页 main 为 1120px；目录描述
只有 760px，所属容器却有 1389px。国家页子卡描述还被 640px 限制，首页部分描述有 480px
上限。它们没有溢出，因此旧验收没有发现这些问题。

## 本轮设计与修改

- 全站共享 `max-w-container = 1440px`，目录、首页、文章、工具、404、页头和页脚使用同一
  容器规则。修改现有宽度 token 的依据就是本轮用户要求；没有改变颜色、阴影或圆角。
- 删除目录专属容器分支以及描述文字的 280–760px 嵌套上限；文字使用所属栏目空间。
  文章已有侧栏仍保留，正文使用正文栏宽，不再在栏内额外缩进到固定 760px。
- 同时清理首页和 404 等标题/说明的重复局部宽度限制，页脚披露说明使用剩余 Flex 空间。

| 1920px 实测 | 修改前 | 修改后 |
| --- | --- | --- |
| 目录 main / header / footer | 1440 / 1120 / 1120px | 1440 / 1440 / 1440px |
| 其他页面共享容器 | 1120px | 1440px |
| 目录与国家 Hero 描述 | 760px | 1389px，与所属容器一致 |

## 额外发现并修复

1. `affiliate-footer.html`：仅一张卡时仍预留两列，导致半幅空白；仅两张实际存在时使用两列。
2. 输入占位文字原为 `rgb(156,163,175)`，调整为设计系统的 muted `rgb(107,107,102)`。
3. `nav.ts`：从菜单链接按 Esc 后焦点落回 BODY；现在回到该菜单的 summary。
4. `404.html`：此前未加载导航关闭逻辑；抽取共用 `nav-script.html`，404 同样支持 Esc 与
   点击外部关闭，且没有因此加载整站其他脚本。
5. 首页关闭 JS 时仍显示无效搜索框；现在隐藏搜索控件，原生国家列表和展开按钮继续可用。

## 验收口径

- 314 页 × 320/390/768/1024/1440/1920px，共 1,884 个组合。
- 检查三个共享容器的宽度与横向坐标，而非只比较整页 scrollWidth。
- 检查所有可见段落和 prose 的额外 max-width，以及普通块内段落相对父内容区的剩余宽度。
- 当前结果：容器不一致 0、额外段落上限 0、异常段落内缩 0、整页溢出 0。
- 与基线相比，314 页主区域正文（忽略布局空白）及链接全量保持一致。
- 搜索、无 JS 列表、普通页/404 菜单 Esc 焦点、单卡宽度、占位颜色分别验证；目录横滑提示
  在实际开始/结束溢出的 1130/1131px 边界与表格状态一致。
- 29 项定点断言最终全部通过。临时恢复基线源码后，其中 22 项新增要求断言失败，已有行为
  继续通过；逐字节还原并重新构建后再次全绿。
- 独立只读评审通过；审查者单独核对 314 页各仅加载一次导航脚本，并实测中英 404 菜单
  关闭后的焦点与无 JS 国家列表。主控另跑全部 346 个决策状态、258 个结果路径及 64 组
  校验器错误 UI，零 pageerror。
- 本机证据位于被 Git 忽略的 `test-results/frontend-alignment/`；发布与线上回读另记 Registry。

正常段落结束和引用块中的语义换行保留；本轮未改国家内容、规则、费用与核验日期。
